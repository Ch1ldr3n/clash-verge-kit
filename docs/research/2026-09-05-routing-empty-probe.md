# 规则分流：空候选隔离运行验证

日期：2026-09-05。对应工单 #2、[规则分流 V1](../specs/2026-09-05-rule-routing-v1.md) A4、A8、A9、A13、A16。

历史状态：本页主体保留 2026-09-05 的有界技术探针与当时的未验证项。2026-09-08 已扩展并重新运行，正式生成器也已接入；当前验收与限制以[Issue #1–#6 总体验收](2026-09-08-routing-v1-acceptance.md)为准，下文旧的“后续”“未验证”清单已被该记录取代。

2026-09-08 新增验证通过：自动定时刷新、非法 HTTP 200、完整下载超时、重启磁盘缓存回退、坏配置应用失败保留旧运行配置。`probe-routing-generated.mjs` 另验证正式 V3 生成脚本、目标 HTTP provider、跨源节点、原 include-all 隔离、关闭保留嵌套，以及首次规则无缓存 503 后配置接受但空规则仍走原路由。仍不将更新失败等同于候选成功消失；UDP、真实业务和用户客户端激活未实测。

## 结论

- 本机 Mihomo `v1.19.29 windows amd64` 实测：**组级**精确过滤后零候选，设置 `empty-fallback: REJECT` 可以阻断本次 TCP/HTTP 合成请求；省略该字段的负对照实际直连到回环目标。
- 一个来源的选中节点消失、另一来源仍有选中节点时，合并 provider 候选仍能通过剩余节点连接，不必增加会抢占候选的显式 REJECT 成员。
- **不要用 provider 自身的 filter 承载全部选择语义。** 更新后零匹配会返回 503，并保留旧节点；组级 `empty-fallback` 此时不会触发。
- 原始 provider 文件为 `proxies: []` 时，同样返回 503，旧候选继续存在且可以连接。下载失败、解析失败与真正成功更新后的候选消失必须分开报告；不能承诺上游更新失败后即时清除旧节点。

## 方法与安全范围

执行 [probe-routing-empty.mjs](../../scripts/probe-routing-empty.mjs)：

```powershell
node scripts/probe-routing-empty.mjs
```

默认读取已安装的 `D:\Clash Verge\verge-mihomo.exe`，可通过 `MIHOMO_BIN` 指定其他**已安装**内核；不下载或安装内核。脚本输出实际版本，不把任意通过运行都当作经过版本矩阵验证。

每次在系统临时目录创建独立合成配置，绑定随机回环 HTTP 代理端口；关闭 DNS/TUN、健康检查和选中项持久化。两个合成 HTTP CONNECT 出站分别返回 SOURCE-A、SOURCE-B，另一个回环服务计数直连请求。通过临时实例的公开 Controller 更新 provider 和切换测试组，并经实际代理端口发送请求。没有接触用户活跃 Controller、真实订阅、系统代理、Clash Verge 配置或远程代理服务器。退出时停止自己启动的内核并删除本次临时配置。

补充 HTTP provider 使用独立回环服务返回合成节点或 503，缓存路径位于本次新建临时目录。测试 provider 的下载显式使用 DIRECT，仅访问回环服务；这不是产品订阅下载策略，不是 AI 流量直连兜底。探针从 mixed-port 改为 HTTP port，避免测试未覆盖的 UDP 监听在 Windows 上绑定失败。

测试边界是规格已经批准的隔离真实 Mihomo 运行行为，不是产品内部函数。本项属于研究探针，没有修改产品生成器，也不宣称完成产品 TDD 红绿循环。

## 实测矩阵

环境输出：`Mihomo Meta v1.19.29 windows amd64 with go1.26.5 Sat Jul 18 12:20:03 UTC 2026`，Node.js v24.15.0。

| 场景 | 实际结果 |
| --- | --- |
| A、B 两来源包含同名 `same[1]`，只选择 A 的该节点和 B 的 `chosen+B` | 候选准确为两个选中别名；首次请求返回 SOURCE-A |
| A 更新为只含未选节点 | 组只剩 B 的已选节点；请求返回 SOURCE-B，未串到 B 的同名未选节点 |
| B 也更新为只含未选节点 | 组公开 API 返回唯一候选 REJECT；请求无成功内容，直连计数不增加 |
| 静态目标节点精确匹配 | 返回 SOURCE-A |
| 静态精确匹配无候选 | 组候选 REJECT，请求被阻断，直连计数不增加 |
| 无候选但省略 empty-fallback 的负对照 | 组候选 COMPATIBLE，请求返回 DIRECT-TRAP，直连计数恰好增加 1 |
| 恢复 B 后把原始 provider 改为零节点 | 更新 503：`file doesn't have any proxy`；组保留 B 已选候选，请求仍返回 SOURCE-B |
| 单独 provider 使用自身 filter，更新为零匹配 | 更新 503：`doesn't match any proxy, please check your filter`；旧候选仍存在 |
| HTTP provider 已有缓存，更新源返回 503 | 验证请求确实到达合成源；更新失败后候选仍为已选节点，请求返回 SOURCE-A |
| HTTP 源恢复 200，返回非空列表但不再包含已选节点 | 更新成功，组仅剩 REJECT，请求阻断且直连计数不增加 |
| HTTP 源首次加载即 503，独立缓存路径不存在 | 组仅剩 REJECT，请求阻断且直连计数不增加 |

脚本对上述成功行为和失败边界都做断言，运行退出码 0 表示**重现了这些结果**，不表示两种失败边界已经解决。

## 来源隔离候选，不是已批准实现

为排除跨来源同名误选，动态成功案例使用专用 provider 的 `override.additional-prefix`（A::、B::），再在同一个出口组做转义、锚定的联合匹配。原始合成来源节点名未改写，但运行期专用副本有别名。这只是证明一条技术路径，**没有决定将别名副本引入产品**。是否符合“不直接改写机场原节点名称”、如何与现有前缀和缓存文件共存，需要后续设计确认；不得把探针简化命名当作正式身份映射或冲突保护方案。官方 [provider 文档](https://wiki.metacubex.one/config/proxy-providers/) 描述了 override 与前缀配置。

## 最低版本证据

官方 [v1.19.27 release](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.27) 明列提交 `1e62d55` 新增可配置 empty-fallback，因此 **v1.19.27 是该能力的首次稳定发布依据**。官方[代理组文档](https://wiki.metacubex.one/config/proxy-groups/#empty-fallback)说明默认 COMPATIBLE、回退只支持 proxy 而非代理组；同页 [filter](https://wiki.metacubex.one/config/proxy-groups/#filter) 说明组级过滤作用范围。

这不等于实测覆盖 v1.19.27：本轮仅运行 v1.19.29，没有安装旧内核，也没有验证旧版本是否静默忽略未知字段。后续若采用此结构，低于能力门槛或版本未知应明确拒绝，不可仅依赖 `-t` 语法成功。产品最低支持版本仍应结合实际版本测试确定。

## 尚未验证与后续边界

- 原始 provider 全空、文件删除、远程下载失败并不必然成为运行期空组。已证明原始空列表和 HTTP 503 更新失败保留旧候选；文件删除与其他下载失败类别仍需单独验证。用户随后确认允许更新失败时保留最后有效的已选候选，因此原始空列表反例不再要求额外强制断网；这不补足尚未进行的测试，不能给 #2 或 A9/A16 全部通过结论。
- 已覆盖文件及 HTTP provider 的公开刷新接口、HTTP 503 后保留当前实例旧候选、HTTP 首启无缓存失败。未覆盖自动定时刷新、进程重启后磁盘缓存回退、下载超时、HTTP 200 非法内容，以及客户端应用失败后保留旧配置的行为。
- 静态案例覆盖有/无匹配的运行配置，未覆盖完整脚本重新激活流程；动态案例是真实更新同一个运行实例。
- 仅测试 TCP/HTTP 回环请求，未覆盖 UDP、长连接、真实 AI 域名、健康探测、测速或所有代理协议。
- 未接入 Kit 主动检查的缺失提示、CLI 节点选择、保存兼容和生成器；这些仍由后续工单实施。
- 2026-09-05 后续确认：用户同意更新失败保留最后有效的已选候选，成功更新后全缺失才阻断；不额外做后台强制断网。正式规格 A9/A16 已同步。此确认不批准其他未决事项，包括来源别名副本、保存格式及规则源影响范围。
