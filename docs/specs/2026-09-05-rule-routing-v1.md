# Spec：规则分流 V1

状态：产品范围已批准；实施设计待验证；尚未实现。
批准日期：2026-09-05。
批准范围：用户确认完整产品范围，并同意整理为本地正式规格；不包含代码实施、GitHub Issue 发布、依赖安装或 Git 提交授权。

## Problem Statement

用户希望从已有订阅中选取节点，让 AI 等特定流量使用指定出口，并能够再次打开工具修改设置。当前 Kit 的正式能力是将子订阅嵌套进目标主订阅，不能把已有的内部 AI 生成逻辑当作已交付的节点选择与规则管理功能。

首期采用 A：手动选择节点、组织出口组、绑定规则。长期 B 的完整节点管理另行定义，不在本规格中提前实现。

## Solution

以目标主订阅为边界，建立通用的“分流方案 = 节点来源 + 出口组 + 规则模块”。首个规则模块是 AI；领域模型不限定为一个固定 AI 组。规则分流可以独立使用，不要求先添加子订阅或选择嵌套入口；也可以与已有嵌套配置并存。

用户流程：

1. 选择语言和本机已导入的目标主订阅。
2. 进入规则分流；首次创建方案，或查看并编辑已保存方案。
3. 启用 AI 模块，复用已有代理组，或手动选取节点创建出口组。
4. 查看“AI → 出口组”、节点来源、候选与缺失项摘要。
5. 确认交付：复制脚本，或通过既有安全流程写入目标已绑定的脚本。
6. 在 Clash Verge Rev 重新激活目标订阅。再次编辑或关闭 AI 后，同样需要保存并重新激活。

保留 CLI 的返回、取消、分页和语言一致性。未保存草稿退出后丢弃；复制脚本不等于已安装、可以自动回读或已经生效。

| 出口方式 | 选择范围 | 节点变化时的行为 |
| --- | --- | --- |
| 复用已有组 | 目标主订阅中可验证引用有效的现有代理组 | 保持原组成员、选择和回退策略，包括其可能存在的 DIRECT |
| 手选节点创建组 | 目标主订阅和子订阅的节点，可跨来源组合 | 部分缺失时剩余节点继续作为候选；全部缺失时阻断，不自动换其他节点或直连 |

子订阅只提供节点，不整套导入其原有代理组。已有 Kit 嵌套子组若能够在目标配置中验证引用和依赖，可以按目标已有组处理；这不等于导入子订阅原有的整套组。

## User Stories

1. 作为用户，我可以只使用目标主订阅配置 AI 分流，无须先建立嵌套配置。
2. 作为已有嵌套用户，我可以添加分流而不丢失原来的子订阅和入口关系。
3. 作为用户，我可以让 AI 复用目标已有代理组，不重复组织节点。
4. 作为用户，我可以手选目标主订阅的节点组成 AI 出口。
5. 作为用户，我可以手选子订阅节点作为出口候选。
6. 作为用户，我可以组合多个来源的已选节点，而不是被迫使用整个订阅。
7. 作为用户，我能区分来自不同订阅的同名节点，避免选错来源。
8. 作为节点较多的用户，我可以通过分页和名称查找完成选择，不必阅读无限长的列表。
9. 作为用户，我希望 Kit 的 AI 规则优先于机场原有规则，使用我指定的出口。
10. 作为用户，我希望普通流量继续遵循原配置。
11. 作为用户，我可以在交付前检查出口、节点和缺失项摘要。
12. 作为用户，我可以重新打开已保存方案，增减节点或更换出口组。
13. 作为用户，我可以关闭 AI 模块，恢复机场当时的原有分流，而非恢复过时快照。
14. 作为用户，我希望部分已选节点消失时仍可使用剩余候选。
15. 作为用户，我在下次打开 Kit 检查时能看到缺失项并重新选择。
16. 作为用户，我希望全部手选候选消失时阻断 AI 连接，不悄悄改走其他出口。
17. 作为用户，我能明确知道复用原组仍遵循其自身策略，不获得额外的阻断保证。
18. 作为用户，我可以取消编辑，保留此前保存的配置。
19. 作为用户，我能区分草稿、已复制、已写入和需要重新激活的状态。
20. 作为用户，我的订阅凭据不会因选择节点或诊断失败而进入默认终端输出或测试记录。

## Implementation Decisions

### 已确认的约束

- 保留 CLI-only、单一生成器和既有安全写入边界；不另起应用或执行引擎。通用分流模型不能被内部固定 AI 预设限制。
- 嵌套入口只约束嵌套功能。仅使用分流时，不强迫用户建立一个没有用途的嵌套主代理组。
- 节点列表来自用户选定的本机配置与受控订阅检查。可以为选择功能提供必要的节点名称和来源标识，但不得展示凭据、原始 YAML 或默认回显完整脚本；也不把检查快照称为实时列表。
- 节点选择至少按“来源 + 名称”隔离，并处理已有前缀、同名和正则转义。不得为实现选择而直接改写机场原节点名称。
- Kit AI 规则必须先于能够截获相关流量的原规则匹配；仅放在 MATCH 前不足以证明优先级。保留原规则及其相对顺序，普通流量行为不变。
- 只增加和维护本模块所需对象，不顺带改写 DNS、TUN 或整个机场模板。
- 复用原组不改成员和回退策略。手选组不能因一个来源变空而遮蔽其他来源的有效候选，也不能让显式阻断项抢占仍存在的候选。
- 名称改变按节点缺失处理；仅依赖名称不能识别同名节点背后的服务器替换，不宣称具有稳定的服务器身份跟踪。
- Kit 主动检查发现全部手选候选缺失时，明确解释原因，允许重选或关闭模块，不把方案报告为可用。已应用配置运行期间全部候选消失时必须阻断；Kit 退出后不主动弹窗或通知。
- 候选消失与候选存在但连接失败是不同状态；本期不承诺测速或健康管理。
- 关闭 AI 时，只清理 Kit 拥有且不再使用的规则与新增对象，保留仍被嵌套或其他配置引用的对象；原配置来自当次运行输入，不用历史快照替换。
- 编辑后重新生成交付结果，不允许导出陈旧草稿；继续执行目标核验、完整脚本识别和并发写入保护。

### 实施前要落实的技术设计

以下是代理负责验证的实施任务，不是要求用户猜测技术答案。若验证结果需要改变以上体验，再带回产品讨论。

| 项目 | 待确定内容与完成依据 |
| --- | --- |
| 保存与回读 | 优先评估通过目标已绑定的 Kit 脚本回读；确定元数据版本、旧格式兼容和完整脚本比对。能解析元数据不代表允许覆盖；未知或已修改脚本必须保留安全拒绝。格式兼容变更实施前另行确认。仅复制但未安装时不得声称已持久保存或可自动回读。 |
| 节点身份与来源映射 | 证明检查列表到生成结果的映射正确，覆盖多来源同名、前缀、特殊字符、来源删除和组依赖循环。 |
| 动态 provider | 按来源表达精确选择；Verge 脚本本身不依赖网络或文件 IO。验证 provider 更新后部分或全部候选消失的实际行为。 |
| 内核兼容 | 核实空组阻断能力的最低版本，覆盖静态和动态节点；旧内核应明确拒绝不兼容方案，或使用经过等效验证的实现，不能静默回退为直连。 |
| AI 规则源 | 选定受控数据源、许可、更新方式和明确覆盖范围，核实 ChatGPT、Claude、Gemini 等预期场景。现有内部生成器使用的集合只是候选，不代表全部覆盖已确认。 |
| 失败状态 | 区分节点缺失、连接失败、检查失败、规则下载失败和脚本应用失败；核实客户端保留旧配置时的实际表现，不把抛错等同于阻断成功。 |
| 开源复用 | 选定具体仓库版本和文件，核对许可、依赖及所需行为；只复用首期必要部分，不整包移入完整处理流水线。 |

## Testing Decisions

优先使用现有最高层测试入口：注入依赖的 CLI 工作流与脚本化输入输出、生成器公开输出、重复应用脚本的配置断言、安全写入的隔离临时目录。通过合成订阅和模拟检查覆盖菜单与失败，不读取或写入用户真实配置。

动态 provider 更新和空候选阻断需要隔离的真实 Mihomo 运行验证。现有配置语法检查可复用，但单独通过 `mihomo -t` 不能证明运行期不会直连。不得为测试修改系统代理或当前 Clash Verge Rev 活跃配置。

### 验收条件

| 编号 | 场景 | 可观察的通过条件 |
| --- | --- | --- |
| A1 | 无子订阅独立配置 | 可以选择目标节点或已有组，完成分流交付；不要求先选嵌套入口。 |
| A2 | 与嵌套共存 | 加入、编辑或关闭分流均保留原有嵌套关系。 |
| A3 | 复用已有组 | AI 指向所选目标组，原组成员和策略不变；不整套导入子订阅原有组。 |
| A4 | 多来源手选 | 只有选中的来源与节点进入候选；同名、特殊字符及前缀不引入其他节点。 |
| A5 | 规则优先级 | 即使原 AI 规则或更宽的匹配规则在前，Kit 指定出口仍优先；非 AI 样例保持原行为。 |
| A6 | 重新打开与编辑 | 已保存方案可恢复、修改节点与出口；交付结果与新设置一致，取消不改变旧保存结果。 |
| A7 | 关闭模块 | 基于当前机场输入恢复原分流，仅移除 Kit 的无用对象；共享嵌套对象保留。 |
| A8 | 部分候选消失 | 剩余候选可继续使用，包括其中一个来源已空、另一个仍有候选的场景。 |
| A9 | 全部候选消失 | 静态与动态场景均不直连、不换成未选节点；下次 Kit 主动检查显示缺失原因并允许重选或关闭。 |
| A10 | 复用原组的边界 | 明示并保留原组自身的 DIRECT 或其他回退，不宣称手选组的阻断保证适用于它。 |
| A11 | 重复应用与引用 | 多次生成、应用、编辑、关闭不累积规则或对象；无悬空或循环引用。 |
| A12 | 保存兼容与安全 | 支持的旧 Kit 格式按确定的兼容方案处理；未知脚本、内容被修改、目标失配和并发变化均不得绕过安全写入。 |
| A13 | 不兼容内核 | 给出明确不兼容结果或通过等效阻断验证，不输出可能静默直连的成功结论。 |
| A14 | CLI 与隐私 | 大列表可分页查找、返回和取消；语言一致；默认输出及错误不含订阅凭据或完整配置。 |
| A15 | 交付与生效 | 复制、写入、重新激活状态清晰；仅复制不被当作已安装或已应用。 |
| A16 | 检查和运行失败 | 检查失败不被误判为“零节点”；连接失败不被误判为候选消失；规则下载与应用失败按实测状态报告。 |

本次只形成文档，不声称上述验收已经通过。实现阶段还应运行项目现有类型、回归和打包检查，并记录隔离运行验证的内核版本与结果。

## Out of Scope

- 长期 B 的自动地区、倍率、线路分类，以及改名、语义去重、排序、测速、健康管理和运行时自动切换。
- AI 之外的规则模块、自定义规则编辑器和完整机场覆写模板。
- 整套导入子订阅代理组，或建立新的通用订阅聚合服务。
- 任意远程可执行脚本、批量接管 DNS/TUN、后台常驻提醒。
- Web/桌面界面、云同步、订阅托管，或替代 Clash Verge Rev/Mihomo 应用配置和处理流量。

## Further Notes

基础可行性已参考 Mihomo 的[空组回退](https://wiki.metacubex.one/config/proxy-groups/#empty-fallback)、[节点筛选](https://wiki.metacubex.one/config/proxy-groups/#filter)及[内置出站](https://wiki.metacubex.one/config/proxies/built-in/#compatible)文档。默认空组回退不能作为“不直连”的保证，具体支持版本和生成结构仍需验证。[Verge 脚本文档](https://www.clashverge.dev/guide/script.html)限定了脚本的 IO 能力，不能让脚本自己抓取实时节点。

开源候选为 [Mihomo-Toolkit](https://github.com/XiaoM-OVO/Mihomo-Toolkit)、[MiSub](https://github.com/imzyb/MiSub) 和 [clashnodeeditor](https://github.com/yanjinbin/clashnodeeditor)。它们分别用于考察构建逻辑、操作模型和编辑校验；本规格不表示已选定或许可整包复制。
