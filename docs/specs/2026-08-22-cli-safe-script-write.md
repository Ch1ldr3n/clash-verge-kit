## 目标

在不引入第二套生成器、不改写整份 `profiles.yaml`、不控制 Clash Verge Rev 重启的前提下，为 CLI 增加：

1. 按 Clash Verge Rev 官方规则识别系统数据目录和便携配置，不依赖软件安装在默认盘；
2. 识别 `profiles.yaml.current` 指向的当前订阅，并默认作为目标主订阅；
3. 保留手工选择其他本机目标订阅的流程；
4. 自动识别失败时允许用户指定安装目录、配置目录或 `profiles.yaml`，但不全盘扫描；
5. 生成后经方向确认，一键写入目标订阅已绑定的独立扩展脚本；
6. ~~复制和写入使用少量行的精简脚本，遮罩预览继续保持可读。~~ 本条已被可读脚本交付规则取代。

## 配置位置识别

标准模式使用官方系统数据目录：Windows 的 roaming AppData、macOS 的 Application Support、Linux 的 XDG data home。Windows 还从正在运行的 `Clash Verge` 进程和卸载注册表读取安装位置，并检查 `<安装目录>/.config/<应用 ID>/profiles.yaml`，以覆盖安装在其他盘的便携配置。所有候选均为有限、可解释路径，不递归扫描磁盘。

自动识别失败时，用户输入一个安装目录、配置目录或 `profiles.yaml`。该位置只在当前 CLI 进程中使用，不写入持久配置。

## 安全写入范围

`LocalProfileRepository.installManagedScript(profileId, script)` 隐藏现场解析和写入细节。它只允许：

- 自动识别或用户明确指定的 Clash Verge Rev 配置根目录；
- 目标订阅 `option.script` 指向、类型为 `script` 的官方 `s*.js` 文件；
- 输入脚本含有效 Kit 管理元数据且 JavaScript 语法有效；
- 原文件为空白、官方默认 no-op 脚本，或完整性校验通过的 Kit 已管理脚本；
- 写入前 `profiles.yaml` 和目标脚本均未发生变化。

未知自定义脚本、异常文件名、符号链接、Windows Junction、真实路径越界、无独立脚本绑定、并发变化或无效脚本均拒绝写入。实现不创建 `.bak`，不修改 `profiles.yaml`，测试只使用临时目录。

## 应用边界

Clash Verge Rev 自己的编辑界面通过内部 Tauri 命令完成“写文件、验证、失败回滚和刷新运行配置”。该命令不是外部 CLI 的稳定接口。因此本增量只负责安全写入已绑定脚本文件；成功后明确提示用户回 Clash Verge Rev 重新激活目标订阅。自动重启或立即应用不在范围内。

## 脚本精简（已取代）

生成器继续保留安全、幂等、更新和复原逻辑。CLI 在交付完整脚本前只做受控压缩：

- 原样保留三行管理元数据块；
- 删除生成器固定的独立注释和空行；
- 去除缩进，并只在原代码行边界内合并；达到约 160 字符后重新分行，避免 Clash Verge Rev 编辑器只显示一条超长横线；
- 压缩后再次进行 JavaScript 语法检查。

测试必须证明管理元数据仍可导入，压缩前后对同一运行配置产生相同结果，并且包含注释字符的用户输入不会被改坏。

当前实现只交付生成器的格式化脚本，保留换行、缩进和固定注释；不得再把多个语句拼到同一行。写入前会按管理元数据重建规范产物并校验整份脚本；仅在判定原文件是否可安全覆盖时，为兼容已经交付的旧脚本，也识别由上述历史精简算法产生且未被修改的确定性产物。

## 验证边界

自动化覆盖标准/便携位置候选、用户指定位置、当前订阅识别、手工改选、默认/Kit 已管理脚本写入、路径穿越、文件链接与目录 Junction 拒绝、未知脚本冲突、无效脚本拒绝，以及格式化脚本的完整性和运行行为。真实 Clash Verge Rev 是否在重新激活后读取新脚本，仍需用户在本机人工验证。
