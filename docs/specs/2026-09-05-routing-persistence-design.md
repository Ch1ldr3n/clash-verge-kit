# 规则分流 V1：保存与兼容合同

2026-09-07 设计；2026-09-08 随用户要求完成 #1–#6 接入实现。本页取代此前使用“版本 2”描述通用模型的提案：版本 2 已用于三分类 `services-v1`，通用模型采用独立的 **版本 3**、生成修订 `routing-v1`，不能按相同版本解释不同结构。

## 保存什么

一个目标、一份已绑定的 Kit 脚本，不新增配置数据库。

| 内容 | 合同 |
| --- | --- |
| targetProfile | 本机目标名称与来源；读取和写入时都重新核验 |
| sources | 方案内唯一 ID、目标/子订阅身份和必要定位信息；不保存完整节点配置 |
| nesting | 可为空；存在时保留原入口、子来源、组名、前缀和移除记录 |
| outlets | 唯一 ID；复用已有组，或引用手选节点，二者互斥 |
| 节点引用 | 来源 ID + provider 身份（静态为 null）+ 原节点名称；保留原名，不混淆跨来源同名节点 |
| modules | 唯一 ID、启用状态、出口 ID、受控规则源 ID/修订；多个模块可共用一个出口 |
| 旧自定义域名 | 保留旧后缀语义，不静默丢弃或换源 |
| 移除记录 | 精确记录 Kit 自有对象及内容指纹；不是按名称前缀删除的授权 |

实际 V3 在 `spec.routing` 保存 sources/outlets/modules；原 parentGroupMode/parentGroupName/children/removedChildren 保留为嵌套部分，`ai` 字段仅为禁用的兼容占位。`legacyAi` 只记录完整识别的旧 AI 出口、来源和规范化后缀，用于精确撤除 V1/V2 遗留规则，不保存旧机场配置。子来源 provider 记录 ID、file/http 定位和更新间隔；不支持的自定义下载策略、传输变换会被明确标为无法核实，而不丢弃参数后假称等价。

首期只交付 AI 模块，模型允许后续分类，不提前实现通用规则编辑器。来源、出口、模块 ID 唯一，引用必须存在；运行组的存在性与循环仍需运行前核对。数组顺序保留。摘要继续遮罩来源凭据，不保存实时健康状态或把节点检查快照当作永久事实。

多个启用模块按 `modules` 数组顺序输出，首个命中生效；若后续支持服务单项例外，应将例外放在综合模块之前。#1 只确定顺序合同，不实现例外菜单。

## 格式与旧版本

新载荷为 `{ schema, version: 3, generatorRevision, spec }`，校验和覆盖全部载荷；外层标记与载荷版本一致。生成修订派发到冻结的归一化与完整脚本重建逻辑。只有解析、目标核对和**全部脚本字节匹配**都通过才可编辑；校验和不是作者签名。未知字段、枚举、版本、修订及重复管理块均拒绝，沿用 2 MiB 限制。

| 原文件 | 处理方式 |
| --- | --- |
| 空白 / 官方默认脚本 | 无已保存方案，可以新建 |
| 支持的 V1 可读 / 历史压缩格式 | 先按原格式完整识别，再转换；冻结已支持字节，不承诺所有历史格式 |
| V1 AI existing | 保留出口、自定义域名和旧规则源；不能无损表达则只读并说明重配需求 |
| V1 AI create | 旧克隆组不是手选节点；只读保留，不能假造手选结果，重配需用户明确选择 |
| 当前 V2 services-v1 | 保留三分类来源身份及出口，不因默认推荐综合分类而静默换源 |
| V3 + 已知生成修订 | 全字节验证后建立编辑草稿 |
| 未知 / 损坏 / 附加代码 / 外部改动 | 拒绝自动编辑或覆盖，不执行输入 JavaScript |

## 编辑、关闭与恢复

1. 只读用户选定目标的已绑定脚本，区分读取失败、没有方案和不支持的脚本。
2. 编辑只改内存草稿，取消和退出不动旧文件；复制不等于安装，不能从剪贴板假定已保存。
3. 保存前重新生成结果，重新核对目标绑定、路径和文件快照；并发变化拒绝覆盖。
4. 写入仍走现有安全入口。成功不代表生效，用户需在 Verge 重新激活。
5. 新启用规则优先于原订阅规则，原规则相对顺序保留；复用组不改成员、选择或回退策略。
6. 关闭时基于当次订阅输入撤除明确属于 Kit 的规则，不能拿旧订阅快照覆盖新订阅。先从启用模块、保留嵌套和外部对象的引用计算仍需保留的依赖，再删除不再使用且所有权已证明的对象。归属不明、同名或内容变化则保留并报告冲突。

恢复原脚本后重新激活，可恢复订阅届时的原有分流；精确恢复历史版本还需历史订阅备份。保存新格式前保留旧脚本副本；旧工具不能读取 V3，单纯切回旧程序不能撤销。用户此前已同意“保留旧设置，不能转换则重新选择，旧文件用于回退”的方向；本轮按此合同实施，仅在交付动作写本机脚本，不自动修改活跃运行配置。

2026-09-08 实现：V3 覆盖前在同目录以独占创建写入 `.kit-backup-<旧内容摘要>`；相同副本只在内容验证一致时复用。保存核对覆盖整个编辑期的索引/绑定/旧脚本快照，写入前再次检查路径与内容；取消不产生写入。备份与脚本均含必要来源信息，不可提交仓库。

运行输入的 Kit 归属记录保留规则行及对象的完整内容指纹；共享对象等值复用且延续归属，在最后外部引用消失后才清理。私有 provider 被原 include-all 组自动收集时，附加精确的别名排除项并记录撤销依据；已有排除项和显式共享引用保留。归属对象、隔离条件被改动或出现同名未知对象时拒绝，不按通用前缀扫删。原 V1/V2 已有组方案的后缀迁移使用原规范化语义；旧输出上的关闭与新鲜输入等价。
